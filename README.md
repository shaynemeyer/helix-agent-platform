# Helix Agent Platform

## Helix is designed around five architectural boundaries

- **Interface boundary:** command-line, web, API, or scheduled clients submit work and receive streamed events.
- **Orchestration boundary**: graphs and functional workflows control state transitions, tools, loops, and interrupts.
- **Capability boundary**: specialist components expose narrow contracts instead of sharing unrestricted context.
- **Data boundary**: checkpoints, long-term memories, retrieved documents, and business records have different retention and access rules.
- **Governance boundary**: authentication, authorization, approval, audit, evaluation, and operational policy constrain behavior.
